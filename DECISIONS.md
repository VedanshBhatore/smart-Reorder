# Decisions Log

One line per decision: what was decided, and why. Chronological.

- Stack: Vite + React + TypeScript + Tailwind, as specified by the brief. No backend; `localStorage` + CSV/JSON export/import covers all persistence needs for a portfolio piece.
- Fictional brand "Basket", neutral teal/charcoal palette, no logos — avoids any Swiggy/Instamart brand-asset reuse while still being visually distinctive.
- Catalogue uses generic product descriptors ("Toned Milk 500 ml") rather than real FMCG brand names, to keep the whole project unambiguously free of third-party trademarks.
- Flow A and Flow B each get their own isolated cart/basket React context, reset per run, so the usability-test harness can run either flow twice in a session without state leaking between them.
- Tap tracking is explicit, not inferred: every interactive element that matters to the task calls `recordTap('expected' | 'mistap')` itself. Inferring "productive vs wasted" taps from DOM structure alone is unreliable; explicit tagging keeps the metric honest and testable.
- "Mis-tap" is defined per-screen at build time (e.g. tapping a disabled/out-of-stock Add button, tapping a bottom-nav item that isn't part of the task) rather than computed heuristically — keeps the definition inspectable in code and in the case study text.
- SUS, tap/time metrics, and counterbalancing are pure functions in `src/lib/` with no React/DOM dependency, specifically so they're trivially unit-testable with Vitest.
- All researcher-facing numbers (research charts, validation charts) are driven by imported CSV/JSON only. Shipped sample files are visibly labelled "Sample data, replace with your research" in the UI, never silently treated as real.
- Survey and usability column mappings live in config files (`src/lib/surveyColumnMap.ts`) so wording tweaks to the real Google Form don't require code changes, only config edits.
- Case-study "Research" insights are hard-coded `[TODO]` placeholders until real survey data is imported and reviewed by the user — the brief explicitly forbids inventing research results.
- Journey map (Teardown section) is a coded step diagram (React/Tailwind), not an image, so it can be edited as data (array of steps) rather than redrawn.
- Flow A's Home screen deliberately has no "psst, try Account → Orders" hint. A moderated usability test measures discoverability of the real navigation path; a baseline that coaches the participant would understate the friction the whole case study is about.
- Checkout and OrderPlaced screens are shared components between Flow A and Flow B (not duplicated) since both flows need byte-for-byte the same address/payment/slot summary — keeps the time/tap comparison between flows about the part that actually differs (getting to checkout), not about checkout itself.
- Each flow owns an internal scroll region for its body only; header, bottom nav, and the "not affiliated" footer stay fixed outside that scroll area. Caught via a scripted Playwright click-through during Phase 2 — the footer was overlapping list content when the whole screen scrolled as one unit.
- "Time to Order placed" stops the instant the confirmation screen renders (via `onReachedPlaced`), not when the participant taps "Done". Done only advances the moderator UI to the SUS form — conflating the two would quietly inflate every completion time by however long the participant lingers reading the confirmation screen.
- FlowA/FlowB keep their "reached placed" callback in a ref, and the effect that fires it depends only on `overlay`, not on the callback itself. The moderator page passes a fresh inline arrow function on every render; depending on it directly caused an infinite `setState`-in-`useEffect` loop (caught via console-error checking in a scripted Playwright run through /test) because each `reachedPlaced()` call produced a new session object, which produced a new inline callback, which re-ran the effect.
- Chart color: Flow A = categorical slot 1 (blue `#2a78d6`), Flow B = slot 2 (green `#008300`) from the dataviz skill's validated 8-hue order — the strongest adjacent CVD pair in that palette — kept deliberately distinct from the app's own basket-green UI chrome so chart identity is never confused with brand color.
- Usability results dashboard defaults to a bundled, clearly-labelled sample dataset (`sampleUsabilitySessions.ts`, fabricated, flagged in the data file and in the UI via `SampleDataBadge`) whenever no real sessions are saved yet, so the page is never an empty shell. It never writes the sample into localStorage — only real `/test` sessions or imported files touch `basket.usability.sessions.v1`.
- Survey column mapping is a flat config array (`surveyColumnMap.ts`) keyed by the exact Google Forms question text, not a generic "detect columns automatically" heuristic — Forms exports use the question text verbatim as the CSV header, so an exact-match config is both the simplest implementation and the one that fails loudly (a listed "missing header" in the UI) instead of silently mis-mapping a reworded question.
- Survey charts use a single hue per chart (not the Flow A/B categorical pair) — each chart shows one variable's frequency distribution, which is a magnitude-by-category job, not an identity/comparison job. Reusing the two-flow blue/green pair here would have falsely suggested every bar belonged to "Flow A" or "Flow B".
- The bundled sample survey CSV is generated through `Papa.unparse` (never hand-typed) specifically to avoid a CSV-quoting mistake: several question headers contain literal commas ("Instamart, Blinkit, Zepto, etc.?"), and a hand-written fixture in a unit test genuinely broke this way during Phase 4 (values shifted into the wrong columns) before being caught by an assertion on response counts — unparse/parse handles the quoting automatically and is what a real Google Forms export does too.
- Text-type survey questions (open-ended) render as a response count plus a handful of verbatim sample quotes, not a word-frequency chart — summarizing free text into something chartable without real NLP would risk misrepresenting what respondents actually said.
